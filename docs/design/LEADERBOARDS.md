# Лидерборды «Кратерики» v0.2 — competitive design

**Статус:** `G1_DESIGN_APPROVED / LOCAL_SCORE_MODEL_IMPLEMENTED / SDK_AND_PORTAL_NOT_CONFIGURED`. Утверждён один all-time лидерборд «Мастерство колонии». G3 вычисляет локальный `careerScore`; публикация и интерфейс таблицы не реализованы.

## Главная таблица: «Мастерство колонии»

**Технический ID:** `kraterika_mastery_v1` (создать в Консоли разработчика Яндекс Игр; пока NOT_CREATED).  
**Тип:** `numeric`, `DESC`, размер десятичной части 0, один основной leaderboard.  
**Кто может смотреть:** любой, если SDK позволяет вывести `getEntries`; список, top-10 и несколько записей рядом с вошедшим игроком.  
**Кто может публиковать:** только авторизованный пользователь после явно выполненного входа и проверки доступности метода. **Нельзя требовать вход для сюжета/ежедневных/достижений.**

### Детерминированная формула

Для каждого из **30 авторских контрактов** хранится лучший *подтверждённый* результат `medal ∈ {0,1,2,3}`, где 0 — не пройден; 1/2/3 — бронза, серебро, золото:

`score = 100 × Σ bestMedal(CT-01 … CT-30)`

- **Диапазон 0…9000**, целочисленный, монотонный, максимум 300 за контракт.
- Одинаковая структурная ценность каждого контракта — соревнуются за степень освоения всей кампании, а не за бесконечный гринд. Не вводить очки от количества нажатий, количества материалов, реального времени игры, рекламы, ежедневных штампов или числа перезапусков.
- Медали определяются **доказанной завершённостью** и per-contract нормативами (логические тики, лимит материала *попытки*, энергия, отсутствие collision). CT-01..CT-06 откалиброваны; `medalTargets: null` у CT-07..30 означает **NOT_CALIBRATED**. Время браузера, FPS и реакция пользователя не входят в формулу.
- При новом best medal вычислить новую сумму из полного сохранённого `bestMedalsByContract`; если итог **не вырос**, не вызывать SDK отправки. Никогда не понижать score из-за переключения устройства или повторной попытки.
- Ничья по сумме остаётся ничьей по инженерному результату. У Яндекс SDK нет подтверждённого на этой стадии пользовательского вторичного tie-break — не обещать сортировку по времени/числу ошибок без отдельной проверки API.

**Пример:** пройдены шесть контрактов, лучшие медали `[3,2,2,1,3,2]` => `1300`; дополнительные попытки без улучшения не увеличивают результат. 30 золотых => `9000`. Учет медалей только после реального `contract.completed` и проверки ID/версии контракта; нельзя засчитывать завершение сегодняшнего G2-R прототипа за `CT-XX` до миграции.

## Интерфейс

Открывается из карты колонии кнопкой **«Лидеры»**:
- «Мастерство колонии», собственное число очков/`9000`, top-10, ближайшие места **если доступны**, пункт «Как начисляются очки» со списком медалей.
- Неавторизованному игроку показывать **свой локальный результат** и общую таблицу, если она доступна. Возможность «Сохранить результат в общую таблицу» с описанием преимуществ и **отдельной явной кнопкой авторизации**. Нажатие на обычную вкладку «Лидеры» не открывает диалог входа.
- Если у профиля скрыты имя или аватар — использовать текст платформы/нейтральный плейсхолдер, не требовать раскрытия данных. Обрабатывать пустые записи, `LEADERBOARD_PLAYER_NOT_PRESENT`, 404 не созданного рейтинга, offline, rate limit, отказ авторизации, fetch errors.
- Уменьшение UI под мобильный экран: top-10 со скроллом внутри, крупный текст и собственная позиция, без принудительного landscape.

## Контракт SDK Яндекс Игр (проверен по официальной документации 18.11.2026)

- Инициализация `YaGames.init()`, `ysdk.leaderboards.getEntries('kraterika_mastery_v1', {quantityTop:10, includeUser:true, quantityAround:3})`. Перед публикацией проверить `ysdk.isAvailableMethod('leaderboards.setScore')` и `player.isAuthorized()`. Отправка `ysdk.leaderboards.setScore('kraterika_mastery_v1', score)`.
- Лимиты из документации: `setScore` не чаще **1/сек**; `getEntries` **20/5 мин**, `getPlayerEntry` **60/5 мин**. Обновлять лидерборд по открытию и вручную не чаще ограниченного интервала, кешировать снимок. Не поллить его каждый игровой тик.
- Лидерборд предварительно создаётся в **Консоли**, иначе SDK может вернуть **404**; запись невозможна без авторизации. При 404 показывать доступный локальный рейтинг и диагностический статус, не «пустая таблица: никто не играет».
- Публикация не входит в текущие Kraterika CI: Ludory Core manifest ≠ SDK integration. Реальные портальные вызовы, настройки и аутентификация — отдельный release gate.

Документация: [Leaderboard SDK](https://yandex.ru/dev/games/doc/ru/sdk/sdk-leaderboard), [Leaderboard setup](https://yandex.ru/dev/games/doc/ru/concepts/leaderboards), [Yandex auth requirements](https://yandex.ru/dev/games/doc/ru/requirements/1/2).

## Честность, границы и угрозы

**Невозможно обещать защищённый от накрутки глобальный рейтинг, если итог формируется только на клиенте**: пользователь может модифицировать localStorage/JS, исходное приложение и `setScore`. Детальные replay hashes и проверки инвариантов в обычном клиенте полезны для выявления ошибок, но **не являются независимой серверной аттестацией**.

Два допустимых режима:
1. **MVP casual:** один all-time рейтинг через штатный SDK с честным предупреждением в архитектурном реестре «client-calculated, anti-cheat NOT_GUARANTEED». Не делать реальные денежные/товарные награды за места. Не позиционировать как защищённый турнир.
2. **Verified competition (отдельный проектный gate):** сервер проверяет подписанную платформой идентичность и replay/команды против server-trusted code+rules, валидирует score и управляет публикацией/хранением; сервис и разрешения/безопасность/эксплуатация должны быть отдельно спроектированы. Пока **NOT_APPROVED / NOT_BUILT**.

Нельзя отправлять SDK подписи/секретные ключи в публичный Phaser bundle. Если backend-верификации нет — никаких официальных призов за места, никакого заявления «невозможно накрутить».

## Еженедельные / ежедневные таблицы — поздний этап

**В v1 не запускать** weekly/daily leaderboard: документация штатного leaderboard SDK не подтверждает возможность программного сброса рейтинга по UTC каждый день и надёжного закрепления честного результата за период. Создавать новый leaderboard с датой «на лету» без Консоли нельзя. Если после аналитики нужен «Челлендж недели», сначала спроектировать собственное period ID, запись best-per-period, независимо проверяемое время и серверную верификацию, затем integration gate. Ежедневные задания [не связаны с публичным лидербордом](DAILY_QUESTS.md).

## Acceptance

- Гость проходит **всю кампанию** и сохраняет личные best medals, а вход для публикации — только по осознанному действию.
- Score ∈ [0,9000], равен сумме максимумов, монотонен, повтор 100 раз не повышает без улучшения, не зависит от daily/achievement/streak.
- SDK unavailable/404/offline не блокируют старт уровня, UI и autosave. Rate limit, protected data, unique player identity, hidden user tested with adapter mocks.
- Real portal scoreboard created, manually configured and проверен на Yandex sandbox/доступной площадке до `LB_RUNTIME_VERIFIED`. **Current: NOT_RUN.**
