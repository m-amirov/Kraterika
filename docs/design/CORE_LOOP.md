# Диспетчерская: контракт геймплея (G1 DRAFT)

## Структура операции

**Игровая задача** — доставить все обязательные контейнеры из источников к соответствующим приёмникам. У операции есть фиксированная карта-сетка, начальное состояние роботов/грузов, набор доступных инструментов, правила энергии и задачи. Не все грузы одинаковы: обычный, хрупкий (не переносить импульсом) и энергоёмкий (транспортная стоимость).

Игрок управляет:
1. размещением в разрешённой области **маршрутных секций** и точек переключения;
2. назначением начального маршрута/робота для каждого груза;
3. режимом **Пауза / Запуск / Один шаг / Повтор**;
4. вручную переключаемой стрелкой, манипулятором (если разрешены уровнем).

События и контракты должны быть представлены данными, а не зашиты в рендер. Подсказки не создают необязательных внешних зависимостей.

## Две фазы

**Подготовка.** Статичная карта; игрок ставит/удаляет допустимые пути, указывает исходные настройки стрелок и размещает инструменты в разрешённом бюджете. На старте нельзя поставить плитку поверх здания, робота, края, препятствия или другой занятой клетки. Любая запрещённая операция оставляет состояние неизменным и сообщает причину.

**Симуляция.** Фиксированный логический тик, предварительное значение **250 мс** при 1× (скорость просмотра может быть 0.5× / 1× / 2×). Результат не зависит от FPS; увеличение скорости лишь исполняет больше тиков в единицу времени. Логические действия игрока в очереди применяются **до следующего тика**, никогда в середине обновления.

Предлагаемый порядок одного тика:
1. Применить валидные команды пользователя в стабильном порядке и списать миссионный бюджет там, где нужно.
2. Обновить манипуляторы/ворота и таймеры cooldown.
3. Для каждого робота вычислить намерение движения и стоимость, не мутируя текущее состояние.
4. Выполнить резервацию целевых клеток: столкновение двух в одной клетке и встречная перестановка запрещены; конфликты получают WAIT без повреждений. Неочевидные конфликты показываются игроку.
5. Одновременно зафиксировать разрешённые перемещения и состояние энергии.
6. Проверить доставку, аварийные условия и win/loss/deadlock. Сформировать события для анимации и звука.

Временный приоритет конфликта — устойчивый ID робота, но приоритет не должен допускать наложения. Для head-on оба ждут, пока игрок не решит тупик. **Детерминизм проверять повторным воспроизведением одинакового списка команд и seed без RNG.**

## Инструменты vertical slice

| ID | Инструмент | Ввод | Ограничение | Обратная связь |
| --- | --- | --- | --- | --- |
| GP-TOOL-01 | Маршрутные секции | Рисование по соседним клеткам | Доступные клетки/число секций в миссии | Подсветка допустимого пути, ошибка установки |
| GP-TOOL-02 | Стрелка | Выбрать развилку, указать выход в паузе/на ходу | Переключение действует со следующего тика | Видимый угол стрелки, направление следующего робота |
| GP-TOOL-03 | Манипулятор | Выбрать груз и допустимую точку выгрузки | Фиксированная зона действия, один груз, cooldown 2 тика | Анимация переноса, освобождённый/занятый слот |

Шлюз и зарядная площадка встречаются как **предустановленные** объекты миссии. Их ручная установка/расширенная автоматика — **post-slice**. У манипулятора нельзя забрать груз у робота в состоянии MOVING в рамках текущего тика, и нельзя выгрузить на занятую или неподходящую клетку.

## Роботы, контейнеры, энергия

- Робот: ID, клетка, направление, груз или EMPTY, батарея (целые единицы), состояние READY/MOVING/WAITING/CHARGING/DELIVERED.
- Груз: ID, тип, адрес назначения, носитель (робот/ячейка манипулятора/хранилище), статус IN_TRANSIT/DELIVERED. Один груз не может принадлежать двум носителям.
- 1 ортогональный шаг = 1 единица батареи, если уровень не задаёт другого; стартовый заряд задаёт карта, предварительно 12.
- WAIT не тратит энергию; зарядная площадка пополняет батарею только если робот на ней стоит и она активна. Нулевая батарея означает ожидание, а не необратимую потерю.
- Хрупкий груз нельзя отправлять через потенциальный будущий «гравитационный импульс», но он может передаваться манипулятором.
- Доставка фиксируется только при совпадении destination ID и контейнера. Лишние/неверно адресованные грузы не засчитываются.

## Ошибки, откат и результат

**WIN:** все обязательные контейнеры имеют DELIVERED, ни один не продублирован; затем фиксируется первая одноразовая награда. **Неуспех:** несовместимый путь/блокировка/нет энергии; игрок может остановить, изменить план или повторить. Не требовать моментального провала только из-за WAIT.

Режим Пауза доступен в любой момент, одиночный «Шаг» — только на паузе. «Отмотать» возвращает точный снапшот последнего тика, включая роботов, грузы, заряды, стрелки, таймеры и историю команд. Для slice ограничить журнал **200 последних тиков**, после чего старые недоступны; всегда есть «Перезапустить» с исходным состоянием. Отмотка не выдаёт наград, а повторная доставка после WIN не выдаёт вторую награду.

**Не должно быть реакции на скорость:** нет таймера истечения, автоматической смерти за 1 промах и обязательного быстрого клика.

## Адаптация и приёмка

- Тач: рисование пути и явный выбор активного инструмента; тапы по стрелке/крану с доступным меню, без hover-only поведения.
- Клавиатура/мышь: Esc — отменить выбор; Space — пауза/продолжить; Shift+S / UI — один шаг в паузе; R — перезапуск после подтверждения.
- Основные состояния и ошибки должны выводиться через видимый UI и доступные labels.
- Единый источник истины — доменная симуляция. Phaser только отображает её и передаёт нормализованные команды.
- Acceptance IDs и тесты: [REQUIREMENTS](../acceptance/REQUIREMENTS.md). Прототип должен проверить конфликт одновременного движения, состояние груза при переносе и восстановление снапшота.
