# Геймплей v0.2 — единая инженерная колония

**Статус:** `G1_DESIGN_APPROVED / G3_CT01_CT06_RUNTIME`. Общая карта лунной колонии **не** заменяется пустыми отдельными 8×8 досками. CT-01..CT-06 реализуют этот цикл; G2-R сохранён как regression fixture, а CT-07..30 остаются `NOT_RUN`.

## От запроса здания к производственному результату

`contract.available → startAttempt → plan → run/pause/step → resolve → commitResult → applyWorldEffects → unlockNext`.

На главной карте игрок видит **функциональные** потребители/производители. Подписанный контракт раскрывает заказ, лимит инструментов, состав техники, влияние на колонию и условия медали. Контракт проходит **на одном из секторов общего мира**; менять сцену для оптимизации Phaser допустимо, но game-state общий.

**Подготовка:** выбран сектор/площадка, игрок строит разрешённые рельсы, ставит зарядные устройства, манипуляторы, распределяет назначенные контейнеры и роботов. Валидатор учитывает препятствия, коллизии, радиус инструмента, ресурсный/энергетический budget попытки. Invalid action → неизменное состояние + понятная ошибка и визуальное выделение причины. Права игрока зависят от уже открытых функций постоянной базы.

**Симуляция:** фиксированный tick (G2-R использует 250 ms для прототипа). Планировочные решения сохраняют смысл при Pause/Step, ускоренная отрисовка и задержки браузера **не меняют результат**. Команды применяются до следующего тика.

**Проверка win:** все обязательные доставленные грузы соответствуют типу и destination; активированы требуемые реальные здания; завершённая операция разрешима и не использует недоступную механику. Win фиксирует один реальный transaction для medal, first-clear, buildings, daily и achievement. Нельзя засчитать только прибытие грузов на поле без функционального потребителя.

## Инструменты и state transitions

| ID | Механика | Действие | Подтверждаемое последствие | Старт |
| --- | --- | --- | --- | --- |
| T-ROUTE | Построить/удалить маршрут | выбрать секцию допустимой сети | доступность перемещения и расход budget попытки изменились | CT-01 |
| T-SWITCH | Переключить/назначить приоритет | выбрать направление общего узла | другой робот прошёл по нужному плечу, без overlap | CT-02 |
| T-CHARGER | Установить/использовать зарядку | назначить позицию/режим зарядки | дальний рейс стал достижимым, зарядка занимает тик/мощность | CT-03 |
| T-ARM | Настроить манипулятор | захватить/перенести в валидный слот | cargo holder переместился; один ID, one source of truth | CT-04 |
| T-BUILDING | Построить/снабдить здание | подтвердить blueprint и поставку | новое state здания, видимый worldEffect и следующий контракт | CT-05 |
| T-DISPATCH | Назначить логистическую задачу | выбрать робота, груз, маршрут/приоритет | два независимых снабжения без fake duplicates | CT-06 и далее |
| T-AUTOMATION | Правило станции | выбрать условие для стрелки/поставки | процесс проходит без обязательного ручного шага | CT-17 (план) |

Расширенные функции вводить поэтапно. Смена направления в паузе не является real-time quick-time event. Пауза, один шаг, перезапуск без штрафа за реакцию — обязательны всегда. На touch нужен настоящий pick/hitbox после scroll/zoom, а не декоративная подсказка.

## Детерминированный тик

1. В стабильном порядке обработать накопленные валидные команды.
2. Обновить зарядку, захваты крана, производственные события и cooldown.
3. Для каждого rover вычислить намерение из snapshot без немедленной мутации позиции.
4. Резервировать целевые клетки одновременно; двойная запись и head-on swap запрещены, WAIT не тратит энергию.
5. Зафиксировать разрешённые движения и затраты энергии; событие передачи груза меняет владельца атомарно.
6. Подтвердить delivery, условия включения/работы зданий, ошибки, новые заказы и лучший medal trace.

**Содержимое события:** `eventId, attemptId, contractId, tick, kind, payload, rulesVersion`. Domain код не импортирует Яндекс SDK, браузерное время, сетевые API или Phaser.

## Ошибки, откат, повтор

Остановка из-за отсутствия пути/заряда должна быть объяснимой и исправимой. Можно pause → изменить схему, step/continue, или restart **только временную попытку**. Перманентные постройки и ранее законченные контракты не теряются. Undo = точный snapshots robots/cargo/battery/switch/equipment/budget/commands; в G2-R нет полного undo, поэтому **NOT_IMPLEMENTED**, не помечать PASS.

У каждого контракта должен быть минимум один source-derived, реально проверенный выигрышный solution trace, negative route tests, отсутствие экономического softlock и реальный браузерный smoke. Gold/Silver пороги установить после решения, не зашивать выдуманные числа в GDD.

## Режимы и сохранения

В UI есть **один мир с контекстом управления**:
- исследование/развитие колонии — выбор района/доступного контракта;
- активная операция — инструменты и показатели выбранной зоны;
- Лунный журнал — достижения/ежедневные задачи;
- Лидеры — рейтинг и необязательная авторизация.

Разделение технических Phaser scenes не создаёт отдельной игровой вселенной. Состояние расписано в [PROGRESSION_SAVES_V2](../architecture/PROGRESSION_SAVES_V2.md).

## Границы MVP и тесты

**G2-R инженерно доказаны:** две поставки, маршрут, стрелка, зарядка, кран, купол, one-time result и browser touch. **Не доказаны:** 30 уникальных контрактов, взаимосвязанные районы, полный постоянный world state, T-DISPATCH/T-AUTOMATION, 3/3 медали, daily/achievements/leaderboard, настоящие игровые спрайты, интеграция платформ.
